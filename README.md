# 八角 · 币安持仓监控与美股短线精选

监控币安代币持仓，在币安美股代币现货交易对中，每天两次由 pi agent 挑选**一周内**有上涨机会的短线候选，给出目标价与止损价。条件不足时可以为零；不自动下单，不保证上涨。

## 全新 Web 控制台

旧 Web UI 已整体替换，不沿用旧布局、Vue 或 CDN。前端为独立 HTML/CSS/JavaScript，无前端安装或构建步骤。

- **持仓监控**：有效持仓、币安报价、未实现盈亏、持仓录入与编辑、止盈/止损、正向涨幅阶梯提醒、独立 AI 分析。
- **短线精选**：候选的目标/止损（USD 与代币 USDT 参考价）、盈亏比、依据、失效条件、风险与来源；运行历史、分渠道重推、5 个交易日复盘与命中率。
- **推送记录**：区分成功、失败，支持状态筛选。研究运行成功不等于消息已送达。
- **配置中心**：ChatGPT 登录（auth.json）、Alpaca、FRED、分析模型、飞书/企业微信、时区调度及默认监控偏好；币安凭据成对验证后独立保存。

桌面使用侧栏与工作台布局，手机使用顶部导航；包含加载、空数据、配置缺失、错误、重试与确认弹窗。页面不展示虚构行情或示例账户。

## 短线精选

- **标的池**：币安 `tokenized-assets`（美股代币化产品）与现货 `exchangeInfo` 求交集，只保留存在 `<代币>USDT` 且状态为 `TRADING` 的标的；不再是固定的 8 只。SPY、QQQ 与板块 ETF 仅作基准，不作候选。
- **流程**：先跟踪已有候选（触及目标/止损/失效），再用 Alpaca 批量日线粗筛，取前 ≤ 12 只，最后每只候选启动一个独立的 pi agent 会话深挖，agent 通过工具自行取数；结论经主服务硬校验后排序，取前 N（默认 5，不足则为 0，不凑数）。
- **因子**：量价动量、趋势结构、波动（ATR%、财报后波动、期权隐含波动）、相对 SPY/QQQ/板块强弱、催化剂（财报、评级变动、新闻、8-K、内部人交易）、市场环境（SPY/QQQ、VIX、宏观日程）、BTC/ETH 联动、币安代币现货可交易性（价差、24h 成交额、溢价）。
- **每个候选**：现价、目标价（含涨幅）、止损价（含跌幅）、盈亏比（≥ 1.5）、5 个交易日有效期、依据、失效条件、风险与引用来源。校验要求目标 > 现价 > 止损，现价与主服务价偏差 ≤ 2%，引用必须来自本会话真实的工具调用。
- **复盘**：满 5 个交易日按正股 USD 日线高低点判断先触及目标还是止损（同日都触及按止损计），并记录第 5 日收盘收益与相对 SPY 超额；控制台展示累计命中率与平均收益。旧的 2～4 周记录只读保留为历史策略，不再复盘。
- **持仓 AI 分析**：美股代币现货持仓改由 agent 以“持仓复核”视角给出持有/减仓/离场观点，不修改实际止盈止损。

**数据来源**

| 数据 | 来源 |
| --- | --- |
| 代币清单、现货可交易性、买卖价差、24h 成交额、BTC/ETH 走势 | 币安（主服务调用） |
| 正股日线/小时线、SPY/QQQ/ETF、新闻 | Alpaca 行情（免费 Basic）与 Alpaca MCP |
| 分析师评级与目标价、财报日期与历史、期权隐含波动、VIX | OpenBB MCP（Yahoo） |
| 8-K 公告、内部人交易 | OpenBB MCP（SEC EDGAR） |
| 宏观日历 | FRED 发布日历（免费 Key）；FOMC 日程为静态表，每年更新 |

**不可得数据**：期权异动/资金流、做空比例、实时订单流、社交情绪。agent 必须如实说明这些数据不可用，不得编造。Yahoo 为非官方接口，可能限流或变更。

**双价格口径**：分析、校验与复盘一律使用正股 **USD**；币安下单参考价为代币 **USDT**，由代币现价按正股目标/止损相对现价的比例换算，仅作参考，代币溢价变化会造成偏差。持仓成本、现价、止盈止损使用代币 USDT。从候选录入持仓只带入代币对，不复制研究价格。行情读取失败显示缺失，不拿成本冒充现价或 0% 盈亏。

**调度与额度**：默认每天 `Asia/Singapore` 09:00（美股收盘后）与 21:00（美股开盘前）各运行一次，时间和时区可在配置中心修改，因子均基于已完成日线。每轮推送新增候选和已有候选的状态变化，无变化时只发一行简报。每天 agent 会话上限默认 **24**（含持仓复核），超出标记为“额度保护跳过”；单会话超时 300 秒、工具调用 ≤ 25、并发 3。无新信息的标的复用上一轮结论。agent 不可用时该轮记为失败，不降级、不生成替代推荐，持仓监控不受影响。

## 首次配置 ChatGPT 登录

分析模型使用你的 ChatGPT Plus/Pro 订阅（pi 的 Codex OAuth），无需 OpenAI API Key。登录需要浏览器，服务器无法完成，因此在本机登录后上传凭据：

1. 在本机安装 pi：`npm i -g @earendil-works/pi-coding-agent`（需 Node.js）。
2. 运行 `pi`，输入 `/login`，选择 ChatGPT Plus/Pro (Codex)，按浏览器提示完成授权。
3. 登录成功后凭据位于 `~/.pi/agent/auth.json`。打开控制台 **配置中心 → AI 服务**，上传该文件；页面会显示登录状态（有效/过期/缺失）。
4. token 会由 agent 自动刷新；过期后重复以上步骤。凭据保存在 `data/agent/`，请保护该目录，不要提交到仓库。

默认使用 ChatGPT 账户中第一个可用的模型（目前通常是最便宜的一个）。想使用更强的模型，请在配置中心填写 **分析模型**。订阅有用量上限，请结合每日会话上限控制消耗。

## 数据源 Key

- **Alpaca**：在 Alpaca 注册免费的模拟盘（paper）账户，生成 API Key 与 Secret（只用于行情与新闻，不会开通交易）；在配置中心 → 数据源填写。
- **FRED**：在 FRED 网站免费申请 API Key，用于宏观发布日历；同样在配置中心填写。
- Finnhub Key 为可选项。这些 Key 只保存在主服务配置中心，agent 每次会话开始时通过内网鉴权获取，无需为 agent 单独设置环境变量。

## 首次启动

需要 Python 3.11+；Docker 镜像使用 Python 3.11。

```bash
# 仅首次安装复制；已有 .env 时不要覆盖。
cp .env.example .env
# 编辑 .env：配置访问密码与币安/通知；数据源与 ChatGPT 登录在配置中心设置。
```

### Docker Compose

```bash
docker compose up -d --build
```

访问 `http://localhost:8000`；接口文档 `/docs`；健康检查 `/api/health`。Compose 启动两个容器：`binance-bstocks-analysis-bot`（主服务）与 `bajiao-agent`（pi agent，`./agent` 构建，仅加入内网 `bajiao-net`，不发布端口）。`data/` 映射至主服务 `/app/data`，`data/agent/` 映射至 agent `/agent-data`（ChatGPT 凭据与内网令牌），请持久化并保护。本文件仅用于本地开发，生产由 CI 的 `scripts/deploy_image.py` 部署。agent 镜像约 1.9 GB，首次分析时 OpenBB MCP 服务约需 12 秒启动。

### 本地运行

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

**只支持单实例、单 worker。**监控锁、AI 补充任务和运行恢复按此模式设计。不要启动多个进程共同监控同一数据库；开发重载也不要连接真实推送渠道。

## 配置顺序

1. 在 `.env` 设置 `ADMIN_PASSWORD`；浏览器使用用户名 `admin` 登录。不设置时页面和接口没有访问认证，必须限制可信网络访问；公网必须另配 HTTPS 与访问限制。
2. 按上文完成 ChatGPT 登录上传，并填写 Alpaca 与 FRED Key；可选填写分析模型。
3. 在配置中心测试各项连接。飞书机器人的自由问答仍使用 `.env`/配置中心的兼容 OpenAI 接口模型，不迁移到 agent。
4. 配置飞书或企业微信 Webhook。点击通知测试会实际发消息；飞书应用机器人配置独立，不替代每日研究的 Webhook 渠道。
5. 按需启用自动短线精选与推送：时间默认 `09:00,21:00`，时区 `Asia/Singapore`，最多候选数、粗筛数量、单会话超时与每日会话上限（24）均可调整。默认调度关闭。
6. 如需同步账户，使用只读币安 HMAC Key/Secret；不要授予交易、提现权限。在页面更换时提交当前 Secret 与完整的新凭据对，账户读取验证成功后才替换。

数据库非空配置优先于环境变量。Secret 不回填或脱敏；留空保留原值。密钥及 Webhook **在 SQLite 中明文保存**，必须限制控制台、数据库、日志和备份访问；不要上传 `.env` 或数据库。浏览器不使用 localStorage/sessionStorage 保存密钥。

## 监控、调度与历史

- 风险扫描独立运行，约每 30 秒检查；单笔默认每 4 小时定期汇报。周期设为 0 只关闭定期汇报，不关闭风险监控。
- 止盈、止损、正向涨幅阶梯提醒与 AI 补充独立；风险消息不等待 AI。成功确认后才记录里程碑或汇报时间，失败允许重试。清空可选提醒价会真正移除该阈值。
- 新增、同步与重新启用已有持仓保留用户偏好；账户读取失败时取消同步，不清空持仓。停止监控不会卖出；后续账户同步可能重新启用仍持有的代币。
- 手动运行默认只更新结果，勾选“本次完成后推送”才发通知。自动运行按所选时区每天两次；错过设定分钟可在当日补跑，每日运行键持久化防止重启重复执行。
- 分析失败保留上次有效报告；隐藏候选不删除历史报告或回顾。通知按渠道和分段保存状态，重试跳过已确认成功的部分。
- 外部渠道已收取消息、进程却未记录成功时仍可能重复投递，不承诺 exactly-once。旧版日志的迁移默认状态不能独立证明历史送达。
- 复盘仅为 5 个交易日的观察统计（正股 USD），不是已实现交易收益，不含滑点/费用，也不能作为策略收益回测。

### 自动发布（CI/CD）

向 `feat/swing-analysis` 推送会自动构建并测试镜像，发布至 GHCR，再部署到现有服务器；健康检查与数据保留检查通过后，仅清理本项目未使用的旧镜像。PR 只测试，不部署。流水线提供失败回滚，不覆盖服务器 `.env`、数据库或其他服务。

首次接入运行 `python3 scripts/setup_cicd.py --ssh-host zendesk-agent-server`，生成专用受限部署密钥并配置 Actions Secrets。完整流程、回滚与清理边界见 [CI/CD 说明](docs/cicd.md)。

原 `scripts/deploy.py` 仅保留作旧版本代码热更新工具。生产切换到镜像流水线后，不要与旧 Compose 源码挂载或热更新脚本混用；依赖变化由新镜像承担。生产由主服务与 agent 两个镜像协同部署，接收端升级需重新运行接入脚本，详见 CI/CD 说明。

当前模块、API 与数据说明见 [短线精选架构](docs/short-term-analysis.md)。旧的历史设计记录位于 `docs/superpowers/`，当前实现与本说明优先。
