# 短线精选改造：pi agent + 工具化数据分析 设计

日期：2026-11-16 · 状态：已确认（2026-11-16）

## 1. 意图与原因

用户只做短线（持有 ≤ 1 周），在币安上通过**代币现货交易对**（如 `NVDABUSDT`，USDT 计价）买卖。希望**每天新加坡时间 09:00 和 21:00** 从**币安上所有美股代币化产品**中选出一周内有上涨机会的标的，并明确看到：能涨到多少（目标价）、跌到哪认错（止损）、为什么（多维数据 + 新闻 + 事件）。

现有流程的问题：Python 预先决定取什么数据、算什么指标，再把一个证据 JSON 一次性丢给模型，模型只能回答"选 / 不选"，无法自己追查数据，分析偏浅；标的池写死 8 只；周期为 2～4 周，与用户的交易方式不符。

用户要求：

- 由 **pi agent**（pi-mono / `pi-coding-agent`）驱动分析，agent 通过工具**自己查数据**，分析更深入。
- 模型使用用户的 **ChatGPT Plus/Pro 订阅**（pi 的 `openai-codex` OAuth 登录），不另付 API 费用。
- 数据源**免费**为主，尽量使用**现成工具**（MCP / skills），只自己写必要部分。
- 部署采用**两个容器**（用户在方案对比中选择 B）。

## 2. 目标 / 非目标 / 反目标

**目标**

1. 每天新加坡时间 09:00 和 21:00 各运行一次，从币安美股代币现货交易对全集中选出 0～N 只（N 可配，默认上限 5）1 周短线候选；不足就是 0，不凑数。每轮推送新增候选和已有候选的状态变化（见 §7.1）。
2. 每个候选给出：现价、目标价（含涨幅%）、止损价（含跌幅%）、盈亏比、有效期（5 个交易日）、依据、失效条件、风险、引用来源。价格同时以正股 USD 和代币 USDT 两种口径展示（见 §5）。
3. agent 使用多维因子（见 §5）和工具自主取数分析。
4. 推荐满 5 个交易日自动复盘：是否先到目标 / 先到止损 / 到期收益，累计命中率。
5. 持仓 AI 分析同样改用 pi agent（持仓复核视角）。
6. 推送、控制台展示、调度、运行历史等现有能力保留。

**非目标**

- 不自动下单、不接任何交易权限。
- 不扫描币安代币以外的美股。
- 不做日内高频 / 盘中盯盘推荐。
- 不做完整回测引擎（只有 5 日复盘统计）。
- 飞书机器人自由问答（`ask_llm`）本期不迁移，继续走现有 OpenAI 兼容接口配置。

**反目标（技术上能跑但算失败）**

- 编造或沿用过期数据、编造新闻 / 评级 / 价格；拿不到的数据假装看过。
- 推荐在币安现货上不可交易、成交量过低或买卖价差异常的代币交易对。
- 输出没有止损、或目标价超出合理波动范围的"喊单"。
- agent 拥有 shell、文件写入或任何交易能力。
- 把代币 USDT 价格与正股 USD 价格混用（两种口径必须分别标注）。
- 重复推送同样的内容刷屏。

## 3. 约束

- 现有服务：FastAPI 单体、Python 3.11、SQLite、**单实例单 worker**；不得破坏持仓监控、账户同步、推送重试。
- 部署链路：GitHub Actions 构建 → GHCR → 受限 SSH 调用 `scripts/deploy_image.py`，按 `@sha256` 摘要切换，失败自动回滚，校验 compose 项目/服务标签。改为两个容器后，该链路必须保持"原子切换 + 失败回滚"语义。
- ChatGPT 订阅 OAuth：官方定位为个人自用（本系统为单用户自用，符合）；登录需浏览器交互，服务器无法完成 → 在本机登录后上传凭据；token 会自动刷新，凭据文件需可写且持久化。订阅有用量上限；每天两轮，需做增量分析和每日会话上限（§7.1）。
- 币安：`/sapi/v1/equity/*` REST **没有历史 K 线**；代币现货对（如 `NVDABUSDT`）K 线是代币成交价、历史短、量小。云端开发环境 IP 被币安地区限制，币安相关逻辑需可离线测试、在用户服务器验证。
- 免费数据源有频率和可靠性限制（Yahoo 为非官方接口）。

## 4. 方案对比（已选 B）

| 方案 | 说明 | 取舍 |
| --- | --- | --- |
| A 同容器子进程 | 镜像加 Node + pi，Python 按需启动 `pi --mode rpc` | 部署链路几乎不改；镜像变大；隔离差 |
| **B 双容器（选定）** | 新增 `agent` 容器（Node + pi SDK + MCP），主服务经内网 HTTP 调用 | 隔离好、可独立升级，agent 故障不影响持仓监控；需改造部署脚本为双镜像协同部署/回滚 |
| C 纯 Python agent | 不用 pi，自写工具调用循环 | 部署最简；但需自行实现 ChatGPT 订阅登录，脆弱且有条款风险 → 排除 |

用户选择 B，理由：隔离与独立升级。

单只候选分析方式：**逐只深挖**（每只候选一个独立 pi 会话，结束于 `submit_pick`；最后由 Python 按规则排序取前 N）。这是我的决定：互不干扰、单只失败不影响其他、上下文短、额度可控。用户未反对。

## 5. 短线因子

| 类别 | 因子 |
| --- | --- |
| 量价动量 | 1/3/5/10 日涨幅；距 20 日高点距离；是否突破；跳空缺口；量比（当日量 / 20 日均量）；收盘在当日振幅位置；连涨/连跌天数 |
| 趋势结构 | MA5/10/20 排列与斜率；相对 MA20 偏离；RSI(2)、RSI(14)；布林带宽度（收口） |
| 波动 | ATR%(14)；近 5 日振幅；历次财报后涨跌幅；期权隐含的一周预期波动（可得时） |
| 相对强弱 | 5/20 日相对 SPY、QQQ、所属板块 ETF |
| 催化剂 | 未来 5 个交易日内财报/事件；近 7 日分析师评级与目标价变动；新闻数量突增；公司公告（8-K）；内部人交易 |
| 市场环境 | SPY/QQQ 短期趋势；VIX；本周宏观事件（CPI、FOMC、非农等） |
| 加密联动 | BTC/ETH 1/5 日走势（COIN、MSTR、HOOD 等加密相关股） |
| 可交易性 | 币安代币现货对的最新价、买一卖一价差、24h 成交额、交易对状态；代币相对正股溢价；正股日均成交额 |

**目标价 / 止损规则**（由 agent 给出并说明依据，Python 硬校验）：

- 目标价参考：上方最近阻力（前高、缺口）、1～1.5×ATR、期权隐含一周波动或历史财报后波动，取保守值。
- 止损参考：近期支撑下方或约 1×ATR。
- 硬校验（`submit_pick` 后在 Python 执行，不通过则拒收）：目标价 > 现价 > 止损；盈亏比 ≥ 1.5；目标涨幅不超过"一周合理波动上限"（以 ATR 与隐含波动推导的上限，具体倍数由实现时确定并写入配置常量）；价格口径为正股 USD。
- 双口径展示（我的决定）：分析与校验均基于正股 USD；展示时按相同涨跌幅换算出代币 USDT 参考价（代币目标 = 代币现价 × 正股目标 / 正股现价，止损同理），并标明"按比例换算，代币溢价变化会造成偏差"。用户在币安下单看 USDT 参考价，判断逻辑看 USD 价。

| 数据 | 来源 | 接入方式 |
| --- | --- | --- |
| 币安美股代币清单（代币 ↔ 正股、乘数） | 币安 `GET /sapi/v1/equity/market/tokenized-assets`（需 API Key，无签名） | 主服务 Python（现有 `binance_client` 扩展） |

| 正股日线 / 小时线、ETF、SPY/QQQ | Alpaca 行情 API（免费 Basic，需注册模拟盘 Key）为主，Yahoo（yfinance）备用 | 主服务 Python（因子计算）+ agent 侧 Alpaca MCP（原始查询） |
| 新闻 | Alpaca 新闻 | Alpaca MCP |
| 分析师评级 / 目标价、财报日期与历史、期权隐含波动、VIX | Yahoo（经 OpenBB yfinance provider）；期权另可交叉参考 Alpaca / CBOE | OpenBB MCP |
| 公司公告 8-K、内部人交易 Form 4 | SEC EDGAR | OpenBB MCP（SEC provider） |
| 宏观日历 | FRED 发布日历（免费 Key）；FOMC 用美联储公布日程（静态表，每年更新） | OpenBB MCP（FRED provider）+ 主服务静态表 |

明确**不可得**（agent 必须如实说明不可用）：期权异动/资金流、做空比例、实时订单流、社交情绪。

新增用户配置：Alpaca Key/Secret、FRED Key、（可选）Finnhub Key；ChatGPT 登录状态。

现有 FMP 依赖：短线流程不再依赖 FMP。

## 7. 架构

```
┌──────────── bstocks-bot（现有，Python） ────────────┐        ┌──────── agent（新增，Node） ────────┐
│ 调度 / API / UI / SQLite / 推送 / 持仓监控           │  HTTP  │ pi SDK 会话（仅自定义工具，         │
│ 1. 拉代币清单 → 2. Alpaca 批量日线粗筛 → 候选 ≤ 12  │ ─────▶ │   禁用内置 read/write/edit/bash）   │
│ 3. 逐只请求 agent 分析（并发 ≤ 3，超时）             │        │  ├─ OpenBB MCP（stdio，白名单路由） │
│ 4. 校验 submit_pick 结果 → 排序取前 N → 入库/推送   │ ◀───── │  ├─ Alpaca MCP（stdio，仅行情+新闻）│
│ 内网 MCP 端点：get_factors / 币安代币工具 / 市场环境 │ ◀───── │  ├─ 主服务 MCP（HTTP，内网+令牌）   │
└──────────────────────────────────────────────────────┘  MCP  │  └─ submit_pick（agent 内置，仅收集）│
                                                                └──────────────────────────────────────┘
```

**主服务（bstocks-bot）职责**

- 标的池：每日从币安 `tokenized-assets` 拉取代币清单并映射为正股代码，再与 `exchangeInfo` 求交集，只保留存在 `<代币>USDT` 现货交易对且状态为 `TRADING` 的标的；SPY/QQQ/板块 ETF 仅作基准。
- 粗筛：用 Alpaca 多标的批量日线接口一次取全池数据，按量价异动、趋势、流动性、近期催化剂打分，取前 ≤ 12 只（阈值为实现常量）。粗筛只是缩小范围，不产生推荐。
- 对外暴露**内网 MCP 端点**（仅 compose 内网可达，共享令牌鉴权），提供：
  - `get_factors(symbol)`：§5 中可由 K 线计算的全部因子数值 + 关键价位（阻力/支撑/ATR），附数据截止时间。
  - `get_token_quote(symbol)`：币安代币现货对最新价、买一卖一价差、24h 成交额、相对正股溢价、是否可交易。
  - `get_crypto_context()`：BTC/ETH 走势。
  - `get_market_context()`：SPY/QQQ 趋势、本周宏观/FOMC 日程（VIX 走 OpenBB）。
- 编排：逐只调用 agent `POST /analyze`，处理超时、失败、取消；校验返回结果（§8）；排序（盈亏比 + 校验通过）取前 N；入库、推送。
- 复盘、展示、配置中心。

### 7.1 运行节奏：每天两次（新加坡时间 09:00、21:00）

用户指定每天新加坡时间（`Asia/Singapore`）09:00 和 21:00 各运行一次；两个时间点均可在配置中心修改。

| 运行 | 对应美东时间（冬令 / 夏令） | 美股状态 | 用途 |
| --- | --- | --- | --- |
| 09:00 SGT | 20:00 / 21:00 ET | 当日已收盘 | 用刚收盘的完整日线和收盘后新闻做主要筛选 |
| 21:00 SGT | 08:00 / 09:00 ET | 开盘前 | 结合隔夜新闻、盘前事件、代币价格复核，开盘前给出更新 |

两个时间点都不在美股常规交易时段内，因子一律基于已完成日线，不存在半根 K 线问题（我据此删除了"盘中补充数据"的设计）。

每轮流程（我的设计）：

1. **跟踪已有候选**（纯 Python，不调用 agent）：有效期内的候选检查是否触及目标、止损或失效条件，代币交易对是否停牌、价差是否异常。
2. **粗筛全池**，得到候选 ≤ 12 只。
3. **深挖**：对候选逐只调用 agent；上一轮已分析且此后没有新新闻、评级变动、公告或明显价格变化的标的，复用上次结论，不重复调用。
4. 校验、排序、入库、推送。

推送：每轮都发一条消息，内容为新增候选、已有候选的状态变化（到目标、触发止损、失效）；没有变化时只发一行"本轮无新增，N 只跟踪中"，让用户知道系统正常运行（我的决定：一天两次不会刷屏，而沉默会让人分不清是没机会还是没运行）。

用量保护：每天最多 24 次 agent 会话（可配置），超出部分标记为"额度保护跳过"。

周末与美股假日：周六 09:00 SGT 一轮仍有周五收盘数据可用；之后的周末轮次通常没有新的正股数据，增量规则会跳过深挖，只做跟踪。

**agent 容器职责**

- Node 服务，内嵌 pi SDK；每次 `/analyze` 新建一个会话（无跨会话记忆）。
- 只注册：OpenBB MCP（白名单：Yahoo 评级/目标价/财报/期权/VIX、SEC 公告与内部人、FRED 日历）、Alpaca MCP（`ALPACA_TOOLSETS` 仅开行情、新闻，不开交易/账户写）、主服务 MCP、`submit_pick`。禁用 pi 全部内置工具。
- 加载项目内置的短线分析 skill（由现有 `analysis_skills/*.md` 改写为短线版，随镜像发布，运行时不下载）。
- 记录本会话**每次工具调用的工具名、参数、返回摘要（含其中出现的 URL）**，为每次调用分配 `call_id`；会话以 `submit_pick` 结束（或明确"不推荐"）。
- 返回：`{decision, pick?, tool_log, usage, error?}`。
- 限制：单会话超时（默认 5 分钟）、最多工具调用次数（默认 25）；均为配置项。
- ChatGPT 凭据：`auth.json` 位于持久化可写卷；`GET /health` 报告登录状态（有效/过期/缺失）。主服务配置中心展示该状态，并说明重新登录步骤（本机 `pi` 执行 `/login openai-codex` 后上传凭据文件；上传入口由实现决定，至少支持手工放置到卷目录）。
- 不持有币安 Secret；不在自身环境变量里长期保存数据 Key。Alpaca、FRED 等 Key 存于主服务配置中心（SQLite），agent 每次会话开始时经内网鉴权接口向主服务拉取，并以环境变量启动本会话的 MCP 子进程（我的决定：用户只需在一处配置，部署不需要为 agent 单独配置环境变量）。主服务与 agent 之间的内网共享令牌存放在持久化卷文件中，不写入 `system_configs`。

## 8. 结论校验（主服务执行）

`submit_pick` 字段：`symbol, decision(selected|rejected), current_price, target_price, stop_price, rationale, invalidation, risks[], factor_highlights[], citations[]`，每条 citation 为 `{call_id, url?}`。

校验：

1. 结构合法；`symbol` 等于请求的标的。
2. 每个 `call_id` 必须在本会话 `tool_log` 中存在；`url` 必须出现在对应调用的返回中。至少引用一次 `get_factors` 与一次新闻/事件类调用。
3. `current_price` 与主服务自行取得的最新价偏差在容差内（防止用错口径/过期价）。
4. §5 价位硬校验。
5. 代币现货对状态为 `TRADING`，24h 成交额高于下限，买一卖一价差低于阈值（阈值按代币现货对成交量很小的现实设定，实现时根据实盘数据校准）。

任一不通过 → 该标的记为 `rejected_by_validation` 并写诊断，不进推荐。

## 9. 数据存储与展示

- 沿用 `analysis_runs` / `daily_picks` / `analysis_deliveries`；`daily_picks.report` JSON 增加 `strategy: short_term_1w`、目标/止损/盈亏比/有效期、`tool_log` 摘要。旧 2～4 周记录保留只读，标记为历史策略，不再参与复盘。
- 复盘改为 5 个交易日（按正股 USD 计）：用日线高低点判断先触及目标还是止损（同日都触及按止损计，保守），并记录第 5 日收盘收益与相对 SPY 超额；控制台展示累计命中率、平均收益。
- 控制台候选卡片（示意）：

```
NVDA / NVDAB   短线 · 1周 · 有效至 11-21
现价 182.40   目标 194.00 (+6.4%)   止损 176.80 (-3.1%)   盈亏比 2.1
依据：放量突破 20 日高点；周四发布会；分析师上调目标价…
失效：跌破 176.80 或发布会后低开
风险：…    来源：[新闻1] [评级变动] [因子]
```

- 卡片与推送同时列出代币 USDT 参考价，例如：`代币 NVDABUSDT 现价 183.10 → 目标约 194.80 / 止损约 177.50（按比例换算）`。
- 推送消息同步该格式，保留"研究价格以正股 USD 为准，USDT 为按比例换算的参考，不保证上涨"提示。
- 配置中心新增：Alpaca、FRED、（可选）Finnhub Key；agent 服务状态与 ChatGPT 登录状态；最大候选数、粗筛数量、会话超时等。

## 10. 持仓 AI 分析

`/api/positions/{id}/analyze` 与持仓监控中的 AI 补充改为调用 agent，`purpose=position_review`：允许看空，输出持有/减仓/离场观点与参考价位，**不修改**实际止盈止损。只对币安美股代币现货持仓（映射到正股）启用；其他资产的持仓不走此流程。复核建议的参考价同样给出双口径。旧 `analyze_candidate` 移除或仅保留给飞书机器人旧路径（实现时决定，不影响行为）。

## 11. 部署

- `docker-compose.yml`：新增 `agent` 服务，仅加入内网，不映射公网端口；挂载 `data/pi/`（凭据，可写）。

- `deploy_image.py`：接受两个镜像摘要；先拉取并校验两者，再按"先 agent 后主服务"切换并做健康检查；任一失败则两者一起回滚到旧版本。保留现有的标签校验、SQLite 备份、串行化与旧镜像清理语义。
